# OpenMAIC Business 护城河加强计划

> **状态：** 规划中
> **创建时间：** 2026-04-21
> **背景：** 应对通用大模型竞争，构建不可替代的产品壁垒

---

## 核心逻辑

**大模型是基础设施，不是产品。** 我们的护城河不依赖"AI 能力更强"，而是以下四者的综合体：

| 维度 | 核心策略 | 关键指标 |
|------|----------|----------|
| 数据壁垒 | 学习知识图谱 + 个性化推荐 | 用户学得越久，推荐越准 |
| 社交网络 | AI 人格搭子 + 学习小组 + 笔记市场 | 用户社交关系链沉淀 |
| 产品体验 | 多智能体协作课堂 + AI 测评 | 多个 AI 协作教学 vs 单一对话 |
| 内容壁垒 | 课程生成方法论 + 认证体系 | 教学设计方法论不可替代 |

## 一、数据壁垒

**现状诊断：** 推荐系统基于 SQL `LIKE` 模糊匹配；测评题目是 mock 数据；无学习行为分析。

### D-001: 学习知识图谱

| 属性 | 内容 |
|------|------|
| 优先级 | **P1** |
| 预计时间 | 3-4 周 |
| 涉及文件 | `recommendations.py`, `assessments.py` |
| 状态 | 待开发 |

**问题：** 测评只记录整体 `mastery_level`，不记录知识点级掌握度。

**方案：**
1. 将每门课程的知识点拆解为图谱节点（如 "Python 基础" → "变量" → "数据类型" → "字符串操作"）
2. 测评题目关联到具体知识点，记录每个知识点的答对率、复习次数
3. 推荐系统基于知识图谱的依赖关系（先掌握 A 才能学 B）

**效果：** 用户学得越久，系统越了解其薄弱环节，迁移成本越高。

### D-002: 学习行为数据采集

| 属性 | 内容 |
|------|------|
| 优先级 | **P1** |
| 预计时间 | 2-3 周 |
| 涉及文件 | 多个 route 文件 |
| 状态 | 待开发 |

**从现有数据点出发，系统性积累：**

| 数据源 | 已有表 | 可挖掘信息 |
|--------|--------|------------|
| 课堂参与 | `classroom_sessions` | 时长、频次、互动活跃度 |
| 测评答题 | `learning_assessments` | 错题模式、答题速度、难度偏好 |
| 笔记内容 | `shared_notes` | NLP 分析内容质量、知识覆盖面 |
| 搭子偏好 | `buddy_configs` | 用户偏好的激励风格 |
| 学习路径 | `learning_paths`, `course_completions` | 学习节奏、完成率、放弃点 |

### D-003: 个性化学习报告

| 属性 | 内容 |
|------|------|
| 优先级 | **P2** |
| 预计时间 | 2-3 周 |
| 状态 | 待开发 |

**功能：**
- 每周/每月自动生成学习报告：进度、薄弱点、对比趋势
- 报告格式：可视化图表 + AI 生成的学习建议
- 报告本身是数据沉淀，无法迁移到其他平台

## 二、社交/网络效应

**现状诊断：** 搭子消息是预设模板（硬编码）；笔记市场功能完整但冷启动困难；问答系统是 CRUD 级别。

### S-001: 搭子从模板升级为 AI 人格

| 属性 | 内容 |
|------|------|
| 优先级 | **P0** |
| 预计时间 | 2-3 周 |
| 涉及文件 | `buddy.py` |
| 状态 | 待开发 |

**问题：** 当前 `buddy.py` 的 6 种搭子都是静态 prompt 模板：
```python
"prompts": {
    "checkin": "太棒了！你今天坚持打卡了，继续保持这份热情！",
    ...
}
```
所有选"鼓励者"的用户收到的是完全相同的消息。

**方案：**
1. 搭子通过 LLM 基于用户的学习数据**动态生成**个性化消息
2. 搭子拥有"记忆"：记住用户的目标、习惯、挫折、突破
3. 搭子的人格随时间演进：从陌生到熟悉，语气逐渐变化
4. 保留 6 种基础人格作为 system prompt 基调

**效果：** 用户换平台等于换一个"懂自己的学习伙伴"。

### S-002: 笔记市场冷启动

| 属性 | 内容 |
|------|------|
| 优先级 | **P2** |
| 预计时间 | 1-2 周 |
| 涉及文件 | `notes.py` |
| 状态 | 待开发 |

**方案：**
1. 用 AI 自动生成课程配套笔记作为种子内容（标注为"AI 助教笔记"）
2. 提高优质笔记作者分成比例（从 70% → 80-85%）
3. 笔记与测评结果联动：测评薄弱知识点自动推荐相关笔记
4. 课程完成时自动引导用户发布笔记（积分奖励翻倍）

### S-003: 学习小组（从搭子到群）

| 属性 | 内容 |
|------|------|
| 优先级 | **P1** |
| 预计时间 | 3-4 周 |
| 涉及文件 | `classroom_sessions.py`, `buddy.py`, `matching.py` |
| 状态 | 待开发 |

**方案：**
1. 基于学习进度自动组队：学同一门课、进度相近的用户推荐组队
2. 小组内有共享笔记、讨论区、进度排行榜
3. 小组可以"毕业"（课程全员完成）获得集体奖励

**效果：** 社交关系链是最强的留存护城河。

## 三、产品体验/技术

**现状诊断：** 多 Agent 对话只取第一个 Agent 回答（`chat.py:35`）；WebSocket 课堂有但只是聊天+白板；测评是 mock 数据。

### T-001: 真正的多智能体协作课堂

| 属性 | 内容 |
|------|------|
| 优先级 | **P1** |
| 预计时间 | 2-4 周 |
| 涉及文件 | `chat.py`, `director_graph.py` |
| 状态 | 待开发 |

**问题：** 当前 `chat.py` 的实现：
```python
first_agent = agents[0] if agents else "teacher"
# 只获取第一个 Agent 的回复
```

**方案：**
1. 多个 Agent 同时参与课堂讨论：
   - **教师** — 讲解核心知识点
   - **学伴** — 提问、分享学习心得
   - **助教** — 答疑、补充说明
   - **挑战者** — 提出进阶问题
2. 流式输出每个 Agent 的回复，标注发言人
3. Agent 之间可以互相回应（学伴提问 → 教师解答 → 助教补充）

**差异化：** ChatGPT 是一个 AI 对你说话，我们是多个 AI 协作教学。

### T-002: 测评 AI 化 + 自适应难度

| 属性 | 内容 |
|------|------|
| 优先级 | **P0** |
| 预计时间 | 1-2 周 |
| 涉及文件 | `assessments.py` |
| 状态 | 待开发 |

**问题：** 当前 `generate_assessment_questions` 是 mock 数据：
```python
question = {
    "content": f"{course['name']}: 问题{i+1} - 测试知识点掌握情况",
    "options": ["选项A", "选项B", "选项C", "选项D"],
    ...
}
```

**方案：**
1. 接入 LLM 基于课程实际内容生成个性化题目
2. 题目类型多样化：选择题、填空题、简答题、代码题
3. 根据用户答题情况**动态调整难度**（答对 → 下一题更难；答错 → 更简单）
4. 错题自动进入复习计划，下次测评优先测试薄弱知识点

### T-003: 学习数据可视化看板

| 属性 | 内容 |
|------|------|
| 优先级 | **P2** |
| 预计时间 | 2-3 周 |
| 状态 | 待开发 |

**功能：** 整合现有所有学习数据为一个可视化仪表盘
- 学习进度趋势图
- 知识点掌握度雷达图
- 社交互动统计（搭子消息、笔记、小组）
- 成就/游戏化进度

## 四、内容/课程壁垒

**现状诊断：** 课程通过 LLM 生成，没有独家内容或教学设计方法论。

### C-001: 课程生成方法论（Pedagogy）

| 属性 | 内容 |
|------|------|
| 优先级 | **P3** |
| 预计时间 | 4-6 周 |
| 涉及文件 | `outline_generator.py`, `agent_generator.py` |
| 状态 | 待开发 |

**方案：** 将课程生成从"让 AI 写大纲"升级为"基于教育心理学框架的课程设计系统"

1. **布鲁姆分类法**：每层对应不同的教学策略
   - 知识 → 定义、概念解释
   - 理解 → 举例、类比
   - 应用 → 实战练习
   - 分析 → 对比、拆解
   - 评价 → 批判性思考
   - 创造 → 项目实战

2. **间隔重复**：课程中自动安排复习节点
3. **认知负荷控制**：每个场景的信息量有上限
4. **费曼技巧**：要求用户用自己的话解释概念

**效果：** 课程质量不取决于用了哪个模型，取决于教学设计方法论。

### C-002: 企业认证/证书体系

| 属性 | 内容 |
|------|------|
| 优先级 | **P3** |
| 预计时间 | 4-8 周 |
| 涉及文件 | `assessments.py`, `recommendations.py` |
| 状态 | 待开发 |

**方案：**
1. 测评结果升级为可验证的证书（含区块链/数字签名）
2. 企业 HR 系统对接 — 学习成果可证明给第三方
3. 行业认证合作：与行业协会/公司认可证书

**效果：** 一旦证书被认可，用户不会放弃已获得的资质。

### C-003: 垂直领域深耕

| 属性 | 内容 |
|------|------|
| 优先级 | **P3** |
| 预计时间 | 持续 |
| 涉及文件 | `programming.py`, `enterprise.py` |
| 状态 | 待开发 |

**方案：**
1. 选 1-2 个垂直领域做到极致（编程 + 数据分析？）
2. 垂直领域的行业知识 + 课程设计 + 测评标准 = 综合壁垒
3. 通用大模型在这些领域的深度不够

## 风险评估

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM 成本过高 | 高 | 分层策略：核心功能用强模型，辅助功能用轻量模型 |
| 社交冷启动失败 | 中 | AI 生成种子内容 + 激励早期创作者 |
| 知识图谱建设周期长 | 中 | 先做 MVP：课程-知识点两级结构，后续细化 |
| 用户不买社交的账 | 中 | 保留"单人模式"作为兜底，社交作为可选增强 |

## 成功标准

6 个月后应该看到：

- [ ] 用户 30 日留存率提升 20%+
- [ ] 平均学习时长提升 30%+
- [ ] 搭子功能使用率 > 60%
- [ ] 笔记市场月活创作者 > 100
- [ ] 测评系统用户满意度 > 4.0/5.0
- [ ] 至少 1 个垂直领域的行业认可
