# 课程创建流程优化方案

## 一、现状对比

| 维度 | Web端 | 移动端 |
|------|-------|--------|
| **步骤UI** | 单页同步展示(输入+大纲+角色同页面) | 4步向导(需求→大纲→角色→确认)，严格分步 |
| **大纲生成** | 非流式(`generateOutlines`)，一次性返回 | SSE流式(`generateOutlinesStream`)，渐进显示 |
| **语言选项** | 固定`zh-CN` | 中文/英文切换 |
| **网络搜索** | 无此选项 | 可选checkbox |
| **Agent交互** | 纯展示，不可选择 | 可toggle每个agent的enabled |
| **场景创建时机** | 创建记录后**同步逐个创建**所有场景，用户等待 | 创建记录后跳转详情页，后台异步创建 |
| **场景创建方式** | 始终逐个`createScene`(120s/场景) | 先`createAllScenes`批量→失败降级逐个 |
| **进度反馈** | 无(只有"创建中...") | SSE实时进度+轮询降级 |
| **表单字段** | topic(单行)+description(可选) | requirement(多行)+language+webSearch |
| **课程名称** | 用户输入的topic | `requirement.slice(0,50)`自动截取 |

---

## 二、移动端现有问题

### P0 — 阻断性体验问题

1. **课程名称自动截取前50字符**，无法让用户自定义课程名称，长需求会生成无意义名称如"我想学习Python数据分析，包含以下内容：数据清洗、特征工..."

2. **大纲不可编辑**，只能全部重新生成。用户无法删除不想要的大纲、修改标题或调整顺序，浪费Token和时间

3. **创建确认页信息过少**，用户无法在最终确认前看到完整的场景列表，不知道即将生成什么内容

### P1 — 重要体验问题

4. **Web端缺少SSE进度反馈**，用户在等待2-5分钟的场景创建时只看到"创建中..."，无法感知进度，容易以为卡死而重复点击

5. **Web端未使用`createAllScenes`批量接口**，串行逐个创建效率低（5个场景可能耗时10分钟），后端已有并行批量接口但前端未对接

6. **大纲生成后Agent自动生成**，但用户在Step 2等待Agent生成期间无退路，不能跳过Agent直接创建课程

7. **Web端课程详情页每次打开都重新生成Agent**（`generateAgentProfiles()`），而非使用已保存的`generatedAgentConfigs`，浪费Token

8. **移动端缺少大纲类型的图标区分**，所有大纲卡片外观一致，用户难以快速区分幻灯片/测验/互动场景

### P2 — 改善性体验问题

9. **Web端无语言选择**，只能中文，而移动端已支持中英切换

10. **移动端Step 0输入区域过于简单**，单一大文本框+语言选择，缺少输入引导和示例

11. **两端的描述字段语义不统一**：Web端`topic`+`description`，移动端只有一个`requirement`

12. **移动端创建后使用`router.replace`**，用户无法通过浏览器后退回到创建页调整

13. **Web端无Token不足的前置检查**，创建到一半才发现余额不足

---

## 三、优化方案

### 方案1：增加课程名称输入字段

**优先级**: P0  
**影响范围**: 移动端 `create.tsx`

**现状**: 课程名称 = `requirement.slice(0, 50)`  
**目标**: 允许用户自定义课程名称

**实现**:
- Step 0 增加"课程名称"输入框（单行，最大50字符），放在需求描述上方
- 默认值: 当用户输入需求后，自动从需求前50字符填充（与现有行为一致）
- 用户可随时修改名称
- 验证: 非空 + 最长50字符

**效果**: 用户可以对课程命名有完全控制权，避免无意义的截取名称

---

### 方案2：大纲可编辑（删除+排序）

**优先级**: P0  
**影响范围**: 移动端+Web端

**现状**: 大纲生成后只能全部重新生成  
**目标**: 支持删除不想要的大纲、拖拽调整顺序

**实现**:
- 每个大纲卡片右上角增加删除按钮(×)
- 大纲卡片支持长按拖拽排序(移动端) / 拖拽排序(Web端)
- 删除后更新outlines数组，场景计数自动更新
- 最少保留1个大纲（删除最后一个时提示"至少保留1个场景"）
- Step 3 确认页同步显示最新大纲列表

**效果**: 减少Token浪费，用户可以精确控制课程内容

---

### 方案3：Web端对接SSE进度 + 批量创建

**优先级**: P1  
**影响范围**: Web端 `create/page.tsx`

**现状**: Web端逐个串行创建场景，无进度反馈  
**目标**: 使用`createAllScenes`批量接口 + SSE进度实时展示

**实现**:
1. `handleCreateClassroom` 改用 `apiClient.createAllScenes(id, outlines, language)`
2. 创建后连接 `/classrooms/{id}/scenes/progress` SSE端点
3. UI层增加进度条: `正在生成场景 (3/5)...`
4. 每个场景完成后更新计数和进度条
5. 批量接口失败时降级到逐个创建(与移动端一致)
6. 全部完成后跳转详情页

**效果**: 创建时间从10分钟降至2-3分钟，用户可感知进度

---

### 方案4：Agent步骤可跳过

**优先级**: P1  
**影响范围**: 移动端 `create.tsx`

**现状**: 必须等待Agent生成完成才能进入下一步  
**目标**: Agent生成可跳过，使用后端默认配置

**实现**:
- Step 2 Agent区域增加"跳过，使用默认角色"按钮
- 点击后调用 `apiClient.getDefaultAgents(language)` 获取默认Agent
- 或直接进入Step 3，标记 `useDefaultAgents=true`
- 确认页显示"使用默认角色配置"

**效果**: 减少等待时间约15-30秒，用户可选择跳过

---

### 方案5：大纲类型图标区分

**优先级**: P1  
**影响范围**: 移动端+Web端

**现状**: 所有大纲卡片外观一致  
**目标**: 通过图标+颜色区分场景类型

**实现**:
| 类型 | 图标 | 颜色标签 |
|------|------|---------|
| slide | 📊 slides | 蓝色 |
| quiz | ❓ quiz | 绿色 |
| interactive | 🔬 interactive | 橙色 |
| pbl | 🛠 pbl | 紫色 |

- 大纲卡片左侧增加类型图标
- 类型文字用对应颜色背景的标签显示
- 筛选标签可按类型过滤大纲

**效果**: 用户一目了然地了解课程场景构成

---

### 方案6：Web端课程详情页复用已保存Agent配置

**优先级**: P1  
**影响范围**: Web端 `[id]/page.tsx`

**现状**: 每次打开课程详情页都调用 `generateAgentProfiles()` 重新生成  
**目标**: 优先使用已保存的 `generatedAgentConfigs`

**实现**:
- `loadAgents` 逻辑改为:
  1. 如果 `stage.generatedAgentConfigs` 存在且非空 → 直接使用
  2. 否则 → `generateAgentProfiles()` → 降级 `getDefaultAgents()`
- 已保存的配置不需要再消耗Token

**效果**: 节省Token消耗，加快页面加载速度

---

### 方案7：Web端增加语言选择

**优先级**: P2  
**影响范围**: Web端 `create/page.tsx`

**现状**: 固定 `zh-CN`  
**目标**: 与移动端一致，支持中英切换

**实现**:
- 表单区域增加语言选择(Toggle: 中文/English)
- 传递给 `generateOutlines` 和 `createFullClassroom`
- 后端已支持 `language` 参数

**效果**: 支持英文课程创建，扩大用户覆盖

---

### 方案8：输入引导与示例

**优先级**: P2  
**影响范围**: 移动端 `create.tsx`

**现状**: 单一大文本框  
**目标**: 提供输入引导，降低使用门槛

**实现**:
- Placeholder文字: "例如：Python数据分析入门，包含数据清洗、可视化、基础统计..."
- 输入框下方显示2-3个示例卡片(点击可快速填充):
  - "Python数据分析入门"
  - "机器学习基础概念"
  - "产品经理必备的数据思维"
- 输入框字符计数(如 0/500)

**效果**: 新用户更容易上手，减少"不知道输入什么"的困惑

---

### 方案9：Token不足前置检查

**优先级**: P2  
**影响范围**: 移动端+Web端

**现状**: 创建到一半才发现Token不足  
**目标**: 在创建前检查余额

**实现**:
- Step 3 确认页显示预估Token消耗: "预计消耗约 {outlines.length * 500 + 2000} Token"
- 调用 `apiClient.getTokenBalance()` 检查余额
- 余额不足时: 红色提示"Token余额不足，请先充值" + 跳转充值页按钮
- 余额充足时: 绿色"余额充足"标记

**效果**: 避免用户花时间填写表单后才发现无法创建

---

### 方案10：移动端创建后使用 router.push 替代 replace

**优先级**: P2  
**影响范围**: 移动端 `create.tsx`

**现状**: `router.replace` 导致无法后退  
**目标**: 允许用户后退到创建页微调

**实现**:
- 改为 `router.push`
- 创建页在 `isFocused` 时检查 `createdClassroomId`，如果已创建则显示"课程已创建，前往查看"按钮而非空表单

**效果**: 更自然的导航体验

## 四、实施优先级

| 阶段 | 方案 | 预估工时 | 收益 |
|------|------|---------|------|
| **Phase 1** (1-2天) | 方案1: 课程名称输入 | 2h | 消除无意义名称 |
| | 方案2: 大纲可编辑 | 4h | 减少Token浪费+提升控制感 |
| | 方案5: 大纲类型图标 | 1h | 信息可读性 |
| **Phase 2** (2-3天) | 方案3: Web端SSE+批量 | 6h | 创建时间减半+进度可见 |
| | 方案4: Agent可跳过 | 1h | 减少等待时间 |
| | 方案6: 复用Agent配置 | 2h | 节省Token |
| **Phase 3** (1天) | 方案7: Web端语言选择 | 1h | 功能对齐 |
| | 方案8: 输入引导 | 2h | 降低门槛 |
| | 方案9: Token前置检查 | 2h | 避免无效操作 |
| | 方案10: router.push | 0.5h | 导航体验 |

## 五、移动端体验专项提升

除上述对齐优化外，针对移动端特有场景的建议：

1. **手势操作增强**: 大纲卡片支持左滑删除(替代删除按钮)，符合iOS操作习惯

2. **键盘优化**: 需求输入框自动聚焦时，键盘上方增加"完成"工具栏，避免键盘遮挡

3. **后台创建的锁屏恢复**: 用户在后台创建场景时切换到其他App，回来后应自动刷新进度(当前SSE连接可能已断开)

4. **离线草稿**: 需求输入未提交时，保存到AsyncStorage，下次打开自动恢复

5. **创建失败重试**: 后台场景创建失败时，在详情页提供"重试创建"按钮(当前只有降级策略，无显式重试入口)

6. **场景预览骨架屏**: 场景正在生成时，显示对应类型的骨架屏(slide/quiz/interactive各有不同骨架)，而非统一loading
