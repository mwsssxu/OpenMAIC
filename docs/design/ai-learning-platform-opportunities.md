## 一、核心定位

**OpenMAIC 的本质：** 将「被动接受知识」转变为「主动探索学习」

| 传统自学 | OpenMAIC 自学 | 体验差异 |
|---------|--------------|---------|
| 看视频/看书 | AI 实时讲解+互动 | 从"看"到"对话" |
| 独自学习 | AI 智能体陪伴 | 从"孤独"到"陪伴" |
| 静态内容 | 动态生成内容 | 从"固定"到"定制" |
| 无反馈 | 即时测验+AI点评 | 从"盲目"到"透明" |
| 难坚持 | 游戏化+学习搭子 | 从"放弃"到"持续" |

## 二、六大扩展方向

### 2.1 输入形态扩展（降低门槛）

**现状：** 文档/PDF → 课程

**扩展机会：**

| 输入形态 | 场景 | 技术路径 | 优先级 | 预计工作量 |
|---------|------|---------|--------|-----------|
| **视频转课程** | YouTube/Bilibili 学习笔记 | 视频字幕提取 + AI 总结 | P0 | 2周 |
| **语音转课程** | 播客/讲座学习 | ASR + 内容结构化 | P1 | 1周 |
| **网页转课程** | 技术博客/教程学习 | URL抓取 + HTML解析 | P1 | 1周 |
| **实物转课程** | 实验操作/手工学习 | 图像识别 + 步骤分解 | P2 | 3周 |
| **问题转课程** | "我想学XX怎么办" | AI 自动搜索+组织资源 | P0 | 1周 |

**用户场景示例：**
```
用户输入："我看了一个量子物理的 YouTube 视频，但不太懂"
AI 行为：
1. 提取视频字幕（调用 YouTube API 或用户粘贴链接）
2. 识别用户困惑点（通过问答交互）
3. 生成针对性讲解课程
4. 配合实验模拟加深理解
```

**实现要点：**
- 视频字幕：集成 YouTube Data API 或第三方字幕服务
- 语音转文字：使用 Whisper API 或本地 ASR
- 网页抓取：使用 Cheerio/JSDOM 解析 HTML
- 问题驱动：结合 Web Search + AI 组织

### 2.2 学习场景深耕（垂直化）

**通用平台的问题：** 内容浅、用户粘性低

**垂直深耕机会：**

| 垂直领域 | 痛点 | OpenMAIC 适配能力 | 市场规模 | 实现难度 |
|---------|------|------------------|---------|---------|
| **编程学习** | 技术更新快、实践难 | 代码沙盒+AI纠错+项目实战 | 50亿+ | 中 |
| **医学教育** | 知识量大、图谱复杂 | 3D解剖+病例模拟+AI诊断训练 | 30亿+ | 高 |
| **法律学习** | 条文枯燥、案例难找 | AI 法官模拟+案例分析+辩论训练 | 20亿+ | 中 |
| **金融投资** | 理论与实战脱节 | 市场模拟+投资回测+AI分析 | 40亿+ | 高 |
| **语言学习** | 缺对话环境 | AI 对话伙伴+文化沉浸+发音纠错 | 100亿+ | 中 |
| **职业技能** | 转行无指导 | 职业诊断+技能路径+项目实战 | 80亿+ | 低 |

**垂直化路径选择：**

```
方案A：通用平台 + 垂直模板（推荐短期）
- 主平台保持通用能力
- 提供"编程模板"、"医学模板"等场景预设
- 用户选择模板后获得领域定制体验
- 优点：复用现有架构，快速验证市场
- 缺点：垂直深度有限

方案B：独立垂直产品（推荐长期）
- 基于 OpenMAIC 技术栈
- 每个领域做独立品牌和产品
- 深耕领域特性（如编程需要代码执行环境）
- 优点：深度体验，品牌认知
- 缺点：开发成本高，团队分散
```

**编程学习垂直模板示例：**

| 功能 | 通用能力 | 编程增强 |
|------|---------|---------|
| 课程生成 | 幻灯片+测验 | +代码示例+可运行片段 |
| 场景类型 | quiz/interactive | +代码沙盒场景 |
| AI 智能体 | 知识讲解 | +代码纠错+最佳实践建议 |
| 导出 | pptx/html | +完整项目代码 |

### 2.5 学习闭环增强（持续动力）

**现状断裂点：**
- 课程完成 → 无后续（断裂点6）
- 学习匹配 → 无协同（断裂点5）
- 反馈 → 无改进（断裂点4）

**闭环增强机会：**

| 闭环 | 功能 | 用户价值 | 实现难度 | 优先级 |
|------|------|---------|---------|--------|
| **学习→复习** | AI 间隔重复提醒 | 抗遗忘 | 低 | P0 |
| **学习→实践** | 项目实战自动生成 | 学以致用 | 中 | P1 |
| **学习→社交** | 学习社区+线下活动组织 | 同伴激励 | 中 | P2 |
| **学习→职业** | 技能→职位匹配 | 直接回报 | 高 | P2 |
| **学习→创作** | 学习者→内容创作者身份转变 | 激励+收益 | 中 | P1 |

**间隔重复复习系统设计：**

```python
# 基于艾宾浩斯遗忘曲线
REVIEW_SCHEDULE = [
    {"day": 1, "duration_minutes": 5, "type": "quick_recall"},
    {"day": 3, "duration_minutes": 3, "type": "key_points"},
    {"day": 7, "duration_minutes": 10, "type": "deep_review"},
    {"day": 14, "duration_minutes": 5, "type": "quick_recall"},
    {"day": 30, "duration_minutes": 15, "type": "comprehensive"},
]

async def create_review_schedule(user_id: str, course_id: str, db: Connection):
    """创建复习计划"""
    course = await get_course(course_id)
    
    for point in REVIEW_SCHEDULE:
        review_id = uuid.uuid4()
        trigger_at = datetime.utcnow() + timedelta(days=point["day"])
        
        await db.execute(
            """
            INSERT INTO review_schedules 
            (id, user_id, course_id, trigger_at, duration_minutes, review_type, status)
            VALUES ($1, $2, $3, $4, $5, $6, 'pending')
            """,
            review_id, user_id, course_id, trigger_at,
            point["duration_minutes"], point["type"]
        )
        
        # 创建通知任务
        await schedule_notification(
            user_id=user_id,
            trigger_at=trigger_at,
            title=f"复习《{course['name']}》",
            body=f"花费{point['duration_minutes']}分钟回顾核心要点",
            action_url=f"/review/{review_id}",
        )
```

**复习场景设计：**

| 复习类型 | 场景内容 | AI行为 |
|---------|---------|--------|
| quick_recall | 5张核心概念幻灯片 | 快速提问"还记得XX吗？" |
| key_points | 关键知识点卡片 | 用户点击查看详情 |
| deep_review | 重新播放核心场景 | AI讲解+互动测验 |
| comprehensive | 综合测验+总结报告 | AI生成学习效果评估 |

## 八、总结

**一句话定位：** 在"AI 解决知识传递"的基础上，构建"学习者全生命周期服务"

**三个关键突破点：**

1. **降低输入门槛** — 从文档到视频、语音、问题，让任何人都能发起学习
2. **增加学习深度** — 从浏览到精通，让付费意愿有层次
3. **打通学习闭环** — 从学完到复习、实践、认证、职业，让学习有持续回报

**下一步行动：**

1. 完成 P0 计划实现（积分比例+会员订阅）
2. 规划 P1 计划（企业功能+扩展方向）
3. 选择一个垂直领域做深度验证（建议：编程学习）
